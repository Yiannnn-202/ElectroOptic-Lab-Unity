# Scene2 元件介绍卡旋转 GIF 美术制作与交付规范

## 1. 文档目的

本文供模型、美术、动画和后期人员制作 Scene2 元件介绍卡中的旋转预览 GIF。交付文件会显示在元件介绍卡左侧预览区，由 Unity 自动读取并循环播放。

本轮需要制作 7 个 GIF，对应 8 个场景目标；起偏器和检偏器共用同一个偏振片 GIF。Unity 端已经接好播放、循环、缩放和加载失败回退逻辑，美术交付后只需覆盖同名文件，不需要改代码、Prefab 或内容资产。

## 2. 一页交付摘要

| 项目 | 统一要求 |
|---|---|
| 文件数量 | 7 个 |
| 文件格式 | GIF87a 或 GIF89a，建议 GIF89a |
| 画布尺寸 | `384 × 384 px` |
| 帧率 | 平均 `15 FPS` |
| 时长 | `4.0 秒`，允许 `3.8～4.2 秒` |
| 帧数 | 建议固定 `60 帧` |
| 循环 | 永久循环，首尾无明显跳变 |
| 背景 | 不透明纯色 `#081A29`，RGB `(8, 26, 41)` |
| 构图 | 单个元件居中，完整展示，四周保留安全边距 |
| 动作 | 元件绕自身竖直轴匀速旋转一周，摄像机固定 |
| 文字 | 不允许出现中文、英文、数字、Logo 或水印 |
| 透明通道 | 不使用透明背景；所有帧均铺满深蓝背景 |
| 建议体积 | 每个文件不超过 `5 MB` |
| 色彩空间 | sRGB |
| 文件名 | 必须严格使用本文指定名称，区分大小写 |

> 注意：GIF 最终会缩小到卡片内约 `176 × 176 px` 的区域显示。细小结构、过细线条和弱对比细节在最终尺寸下可能不可见，必须按小尺寸预览检查。

## 4. 画面设计要求

### 4.1 背景

- 每一帧必须完整铺满纯深蓝背景 `#081A29`。
- 背景应为不透明色，不要使用透明背景、Alpha 渐隐或透明棋盘格。
- 背景不能出现地平线、摄影棚墙角、场景网格、环境图片或大面积渐变。
- 允许在元件附近使用极轻微的深蓝接触阴影，但四角和画布边缘应保持 `#081A29`。
- 不要把卡片边框、扫描圆环和角标画进 GIF，这些装饰由 Unity 覆盖在 GIF 上方；准星已从卡片模板移除，也不要在 GIF 中补画。

### 4.2 元件构图

- 画面只出现一个元件，不出现人物、手、工具、其他仪器或实验场景。
- 元件旋转中心放在画布中心附近，整个循环内不能明显左右漂移或上下跳动。
- 建议元件主体占画布宽高的 `65%～78%`。
- 元件最外轮廓距离画布边缘至少 `40 px`；旋转到任何角度都不能裁切。
- 元件底座可以略低于画面中心，使视觉重心稳定，但不要贴近底边。
- 相机固定，建议使用正交相机；如使用透视相机，使用中长焦并控制透视变形。
- 推荐视角为略微俯视的正面三分之四视角，俯角约 `10°～20°`。

### 4.3 旋转动作

- 元件绕自身竖直轴完成 `360°` 匀速旋转。
- 摄像机、灯光和背景保持不动，不采用镜头环绕元件的做法。
- 第一帧与循环终点必须为同一姿态；导出时不要同时保留 `0°` 和重复的 `360°` 终点帧。
- 不使用突然加速、减速、回弹、停顿、摇摆或往返旋转。
- 不加入位移、缩放、爆炸分解、装配演示或部件开合动画。
- 旋转方向全套保持一致，建议从俯视角观察为顺时针。

推荐 60 帧的角度设置：

```text
第 0 帧：0°
第 1 帧：6°
第 2 帧：12°
……
第 59 帧：354°
循环后回到第 0 帧：0°
```

### 4.4 材质、灯光和颜色

- 模型外观应尽量匹配 Unity 场景中的实际元件，不擅自改变结构和主色。
- 使用冷色、柔和、均匀的棚拍式灯光，确保深色背景上轮廓清晰。
- 可使用克制的青蓝轮廓光，推荐接近 `#40DBFF`，但不能形成强烈霓虹光晕。
- 避免纯黑模型与背景融为一体；暗部仍应保留可辨识的结构层次。
- 金属高光不能过曝，玻璃和镜片不能出现大面积纯白反射。
- 不使用红、黄、绿、紫等大面积装饰光。元件模型本身已有的必要颜色可以保留。
- 不使用强 Bloom、镜头光斑、运动模糊、景深或胶片颗粒。

### 4.5 禁止内容

GIF 中不得出现：

- 元件名称、参数、说明文字、刻意添加的字母或数字；
- Logo、品牌标识、水印、作者签名；
- UI 卡片边框、按钮、准星、扫描环、网格和装饰角标；
- 鼠标指针、选中框、坐标轴、骨骼、辅助线和软件界面；
- 红色错误占位、加载图标或“待制作”文字；
- 白底、透明底、复杂实验室场景或全息投影效果。

如果实际模型带有无法移除的设备铭牌，应保证缩小后不可读，不要额外增强铭牌清晰度。

## 5. 各元件的辨识重点

### 5.1 激光器 `Laser.gif`

- 出光口、镜筒或激光器主体方向必须清晰。
- 保留底座和安装结构，使其与普通圆柱体区分。
- 不需要绘制长距离激光束；如模型自带短出光提示，应保持克制且不遮挡主体。

### 5.2 偏振片 `Polarizer.gif`

- 必须能看出圆形偏振片、镜框和旋转支架的组合。
- 由于起偏器和检偏器共用此文件，不加入“起偏”“检偏”文字或独有标记。
- 使用两者都适用的通用外观，不制作两个不同版本。

### 5.3 晶体盒 `CrystalBox.gif`

- 突出盒体、晶体安装位置和姿态调节结构。
- 旋钮和支架不应因背景过暗而消失。
- 不展示具体晶体参数，也不在盒内增加发光特效。

### 5.4 扩束镜 `BeamExpander.gif`

- 保证镜片、镜筒和支架的层级清楚。
- 透明镜片应有适量边缘反射，但不能像实心金属圆盘。
- 不绘制锥形光束示意线，以免与 Unity 卡片装饰冲突。

### 5.5 光屏 `Screen.gif`

- 正面屏幕和背面结构都应在旋转中可辨识。
- 光屏模型本身的十字标记属于设备结构，可以保留。
- 不在屏幕上叠加动态光斑、干涉图、文字或测量数据。

### 5.6 光电接收器 `PhotoReceiver.gif`

- 突出接收器主体、入光孔和安装支架。
- 轮廓和体量应明显区别于光电二极管探头。
- 屏幕或面板上不生成可识别数字。

### 5.7 光电二极管 `Photodiode.gif`

- 突出传感器探头、感光面或接口结构。
- 不允许直接复制光电接收器后仅改变颜色。
- 如果模型较小，可适当提高画面占比，但仍须保留 `40 px` 安全边距。

## 6. 推荐制作流程

### 6.1 三维软件渲染

1. 使用与 Unity 场景一致的模型、材质和基本比例。
2. 把模型原点或旋转轴放在元件视觉中心，竖直方向与世界 Y 轴一致。
3. 固定相机和灯光，只旋转模型或转台。
4. 设置 4 秒、15 FPS，共 60 帧。
5. 第 0 帧设置 `0°`，第 59 帧设置 `354°`，使用线性插值。
6. 先渲染为无损 PNG 序列，画布可直接使用 `384 × 384`；需要抗锯齿时可先以 `768 × 768` 渲染，再高质量缩小。
7. 合成时在所有帧最底层铺满 `#081A29`，确认没有透明像素。
8. 输出 GIF 前先以 `176 × 176` 预览一次，检查辨识度和边缘清晰度。

建议保留 PNG 序列和工程源文件，GIF 只作为最终运行时交付物。

### 6.2 Photoshop 导出建议

1. 使用“文件 > 脚本 > 将文件载入堆栈”导入 PNG 序列。
2. 在时间轴中创建帧动画，检查帧顺序。
3. 设置永久循环。
4. 60 帧时使用以下延时循环，可得到精确 4 秒、平均 15 FPS：

```text
第 1 帧：0.07 秒
第 2 帧：0.07 秒
第 3 帧：0.06 秒
之后按 0.07、0.07、0.06 重复，共 60 帧
```

5. 选择“文件 > 导出 > 存储为 Web 所用格式（旧版）”。
6. 格式选择 GIF，尺寸设为 `384 × 384`，循环选项设为“永远”。
7. 颜色建议先使用 256 色；如体积过大，可尝试 128 色并逐项检查材质渐变。
8. 仿色建议从 `0%～30%` 之间测试，以不产生明显噪点和色带为准。
9. 关闭透明度，确保背景色已经烘焙进每一帧。
10. 不使用有损参数强行压缩到模型边缘破碎。

如果使用的工具只能统一设置帧延时，可以使用每帧 `0.07 秒`；此时总时长约 4.2 秒，仍在允许范围内。

### 6.3 After Effects 或其他软件

- After Effects 工程建议先输出 PNG 序列，再由 Photoshop、Adobe Media Encoder 或可靠的 GIF 导出工具编码。
- 不要把 MP4、WebM 或 APNG 改扩展名伪装成 GIF。
- 导出后必须重新打开最终 GIF 检查帧数、循环和背景色，不能只检查源工程预览。

## 7. 编码兼容性与体积控制

为了兼容项目中的 Unity GIF 解码器，建议遵守以下规则：

- 使用标准 GIF87a 或 GIF89a，不使用 APNG/WebP 特性。
- 使用完整的 `384 × 384` 逻辑画布。
- 每帧延时不得为 `0`，也不要小于 `0.02 秒`。
- 建议使用全局调色板或常规自适应调色板，避免非标准编码器扩展。
- 建议关闭交错扫描；如果必须开启，交付前需要在 Unity Prefab Lab 中实测。
- 推荐所有帧为不透明完整画面，减少透明色与帧处置方式造成的残影风险。
- 每个 GIF 建议不超过 `5 MB`；超过后 Unity 会给出体积警告。
- 如文件超过 `5 MB`，优先减少噪点、复杂渐变和无意义背景变化，不优先降低尺寸或帧率。
- 未经确认不要低于 `384 × 384`、12 FPS 或 48 帧。

## 9. Unity 替换方式

1. 在文件管理器中打开：

```text
ElectroOptic-Lab/Assets/StreamingAssets/ComponentInfoCard/
```

2. 用美术交付的 7 个 GIF 覆盖当前同名占位文件。
3. 不要删除或替换旁边的 `.meta` 文件，否则 Unity 资源 GUID 会改变。
4. 返回 Unity，等待资源刷新完成。
5. 打开以下场景并进入 Play Mode：

```text
Assets/Scenes/Scene2_ComponentInfoCard_PrefabLab.unity
```

6. Lab 场景会自动播放 `Laser.gif`。其他文件可通过临时修改预览驱动文件名或在 Scene2 悬停对应元件检查。
7. 执行以下 Unity 菜单验证：

```text
ElectroOptics/UI/Component Info Card/Validate Prefab Lab
ElectroOptics/UI/Component Info Card/Validate Hover Interaction In Scene2
```

- [ ] 背景为不透明 `#081A29`，四角没有透明或其他颜色。
- [ ] 元件完整显示，任何角度都没有碰到画布边缘。
- [ ] 元件旋转中心稳定，没有漂移、抖动或缩放变化。
- [ ] 摄像机、灯光和背景没有跟随旋转。

## 11. 验收标准

出现以下任一情况需退回修改：

- 文件名错误、文件缺失或不是标准 GIF；
- 尺寸不是 `384 × 384`；
- 背景不是不透明 `#081A29`；
- 首尾跳帧、旋转不满一周或明显停顿；
- 元件在旋转过程中被裁切；
- 出现文字、Logo、水印、UI 边框或透明棋盘格；
- 小尺寸下无法辨识元件；
- 光电接收器与光电二极管几乎无法区分；
- Unity 中出现残影、花屏、解码失败或播放速度明显异常。

建议验收顺序：

1. 先检查文件名、尺寸、帧数、时长和体积。
2. 再检查深蓝背景和无缝循环。
3. 在 `176 × 176 px` 尺寸检查辨识度。
4. 最后进入 Unity Prefab Lab 和 Scene2 实际检查叠放、清晰度与播放速度。
