# Scene2 流程指引 GIF 美术制作与交付规范

## 1. 文档用途

本文用于制作 `Scene2.The Lab` 实时流程卡片中的六段“视频指引”GIF。规格以当前 Unity 运行时代码为准，交付后按固定文件名放入项目即可，不需要修改播放器代码。

## 2. 最终交付规格

| 项目 | 美术推荐值 | 程序约束/说明 |
|---|---|---|
| 成品尺寸 | **960 × 540 px** | 16:9；当前项目建议的最大分辨率 |
| 宽高比 | **16:9** | 播放器保持原比例完整显示，不裁切 |
| 文件格式 | **GIF89a** | GIF87a 也可解码，优先 GIF89a |
| 帧率 | **15 fps** | 最大建议 20 fps；不要使用 30/60 fps GIF |
| 推荐时长 | **8～15 秒** | 复杂步骤可延长，最大建议 30 秒 |
| 循环 | **无限循环** | 首尾衔接自然；结果画面建议停留 0.8～1.2 秒 |
| 文件大小 | **单个尽量 ≤ 12 MB** | 超过 20 MB 时程序警告，且不保证流畅播放 |
| 颜色 | sRGB、128～256 色 | 优先保证操作对象、光束和光屏变化清楚 |
| 背景 | 不透明完整画面 | 不使用透明背景，避免 GIF Alpha 和处置帧问题 |
| 音频 | 无 | GIF 不包含音频 |

### 一句话交付标准

> 六个文件全部导出为 960×540、15 fps、8～15 秒、无限循环、单文件不超过 12 MB 的 GIF89a。

当前播放器不会因分辨率、帧率或时长超标而主动拒绝文件；只有文件超过 20 MB 时会输出警告。上表是本项目的美术交付与验收标准，不应把“可以解码”理解为“适合提交”。

## 3. 尺寸选择依据

当前视频指引 UI 使用以下尺寸：

- `WindowsCanvas` 参考分辨率：`1920 × 1080`，Match 为 `0.5`；
- 视频弹窗：`960 × 640`；
- 弹窗内实际视频视口：`892 × 482`；
- GIF 使用 `AspectRatioFitter / FitInParent`；
- 画面始终完整显示，允许留边，不会裁切或拉伸；
- 16:9 GIF 在参考分辨率下实际约显示为 `857 × 482`，左右各留约 `18 px` 深色边距。

因此最终 GIF 使用 `960 × 540` 已能覆盖实际显示清晰度。`1280 × 720` 可以作为美术母版保留，但不建议直接作为项目 GIF：它在 1920×1080 界面中仍会被缩小，同时增加 GIF 体积、解码量和运行时内存。

播放器采用 3 帧有界缓冲。`960 × 540` 的单帧 RGBA 像素约占 `1.98 MiB`，三帧约占 `5.93 MiB`，另有当前帧和运行时纹理开销。不要提交 1920×1080 GIF。

## 4. 固定文件名和内容要求

文件名区分大小写，不得加入中文、空格、版本号或额外后缀。

| 阶段 | 最终文件名 | GIF 必须清楚表现的动作 |
|---|---|---|
| 放置光屏 | `PlaceScreen.gif` | 选择光屏，使用 WASD 移动到导轨，按 Space 放下，并展示光屏收到激光 |
| 校准激光 | `CalibrateLaser.gif` | 微调激光，使红点进入光屏中心区域；稳定后按 Enter 锁定校准 |
| 验证消光 | `VerifyExtinction.gif` | 依次放置起偏器和检偏器；先调至近似平行建立亮态，再将检偏器旋至正交，展示光屏变暗 |
| 观察锥光干涉 | `ObserveConoscopic.gif` | 按正确顺序放置扩束镜和晶体盒，保留两偏振器与光屏，展示光屏切换为锥光干涉图样 |
| 更换光功率计探头 | `InstallPowerMeterProbe.gif` | 取下光屏和扩束镜，放置光功率计探头，最后双击“功率计”进入数据处理场景 |
| 更换光电二极管探头 | `InstallPhotodiodeProbe.gif` | 取下光功率计探头，放置光电二极管探头，最后双击“示波器”进入数据处理场景 |

## 5. 画面与构图规范

### 5.1 录制内容

- 录制 Unity 游戏运行画面，不出现 Unity Editor 面板、Windows 标题栏、任务栏或录屏软件界面。
- 画面只保留理解当前操作所需的实验场景和 UI。
- 录制时隐藏流程指引卡片和视频弹窗本身，避免出现“界面套界面”。
- 不展示与当前阶段无关的鼠标操作、调试面板、Console、Gizmo、碰撞体或统计信息。
- 鼠标应平稳移动，点击停顿明确，避免高速抖动和无目的绕行。
- 除阶段需要切换特写外，保持镜头稳定，不进行多余旋转、缩放或快速切镜。

### 5.2 安全区域

- 关键元件、鼠标点击位置、光斑和操作结果放在画面中央约 90% 区域内。
- 四边至少预留 `32 px`，不要把关键信息贴边。
- 文字不是主要信息载体；指引标题和正文已由 Unity 在 GIF 外显示。
- 必须提示按键时，只保留简短键帽：`WASD`、`A/D`、`Space`、`Enter`。
- 键帽、箭头或点击圈统一使用平台青蓝色，避免红色错误提示风格。

### 5.3 清晰度重点

- 光屏红点、明暗变化和锥光干涉图必须能在约 `857 × 482` 的实际显示尺寸下辨认。
- 激光光束不能因 GIF 调色板压缩而断裂或闪烁。
- 深色元件与深色背景之间应保留足够的轮廓光或明度差。
- 不使用细于最终成品 `2 px` 的关键线条。
- 不加入大面积噪点、颗粒、辉光或频繁渐变，这些内容会显著增大 GIF 体积。

## 6. 六段 GIF 分镜建议

### 6.1 `PlaceScreen.gif`

1. 初始画面显示光屏位于元件区。
2. 鼠标点击光屏。
3. 显示 WASD 移动过程，光屏靠近导轨目标位置。
4. 显示 Space 键提示并完成吸附。
5. 停留在光屏接收到激光的结果画面。

### 6.2 `CalibrateLaser.gif`

1. 明确展示光屏红点偏离中心的初始状态。
2. 使用微调操作让红点逐步接近十字中心。
3. 红点进入中心区域后短暂停留。
4. 显示 Enter 键提示并锁定校准。
5. 最终画面保持红点居中。

### 6.3 `VerifyExtinction.gif`

1. 放置起偏器，再放置检偏器，保证光路顺序清楚。
2. 先展示两者近似平行时的亮态光屏。
3. 旋转检偏器至与起偏器近似正交。
4. 同屏或连续展示光屏亮度逐渐降低。
5. 在接近消光的结果画面停留。

### 6.4 `ObserveConoscopic.gif`

1. 保留已安装的起偏器、检偏器和光屏。
2. 将晶体盒放在两偏振器之间。
3. 将扩束镜放在晶体盒前方。
4. 最终光路应表现为：激光 → 起偏器 → 扩束镜 → 晶体盒 → 检偏器 → 光屏。
5. 展示光屏切换并出现锥光干涉图样。

### 6.5 `InstallPowerMeterProbe.gif`

1. 从锥光观察完成状态开始。
2. 取下光屏和扩束镜。
3. 将光功率计探头放在晶体盒后方导轨上。
4. 鼠标移动到名称为“功率计”的元件并明确双击。
5. 以进入数据处理场景作为结果反馈；切场景过程不要长时间停留在黑屏。

### 6.6 `InstallPhotodiodeProbe.gif`

1. 展示光功率计探头已在轨的初始状态。
2. 取下光功率计探头。
3. 将光电二极管探头放在晶体盒后方导轨上。
4. 鼠标移动到名称为“示波器”的元件并明确双击。
5. 以进入示波器场景作为结果反馈；切场景过程不要长时间停留在黑屏。

## 7. 录制与导出流程

### 7.1 推荐母版

- 在 `1920 × 1080` 游戏窗口中录制。
- 母版建议保存为 H.264 MP4，`1920 × 1080`、30 fps 或 60 fps。
- 剪辑时先处理镜头、鼠标节奏和停留时间，再统一缩放和降帧导出 GIF。
- 母版不要只保留 GIF，便于后续修改操作节奏或重新压缩。

### 7.2 GIF 导出

- 尺寸：`960 × 540`。
- 帧率：`15 fps`；若动作很慢可降至 `12 fps`，不得高于 `20 fps`。
- 调色板：优先 256 色；体积过大时可尝试 128 色。
- 抖动：适中，优先保证光束、红点和干涉图连续；避免过强噪点抖动。
- Transparency：关闭。
- Interlaced：关闭。
- Looping：Forever。
- 删除无变化的重复帧，但不要破坏按键提示和最终状态停留。
- 避免激进有损压缩造成文字边缘、光束或光斑闪烁。

### 7.3 Photoshop“存储为 Web”参考

```text
Format: GIF
Colors: 256（体积过大时再降到 128）
Dither: 70%～100%，根据光束和干涉图效果调整
Lossy: 0～10
Transparency: Off
Interlaced: Off
Image Size: 960 × 540
Looping Options: Forever
```

Photoshop 只负责最终压缩时，应先在剪辑软件中把素材处理为 15 fps；不要直接把 30/60 fps 的所有帧原样导入 GIF。

## 8. 程序播放行为

- 文件从 `StreamingAssets/ExperimentGuide` 按固定名称读取。
- 点击“视频指引”后从第一帧开始播放。
- GIF 结束后播放器会重新从压缩数据解码并持续循环。
- 播放计时使用 `unscaledDeltaTime`，不受实验暂停影响。
- 纹理使用 `RGBA32`、Bilinear 过滤，不生成 Mipmap。
- GIF 关闭后会取消解码、清空 3 帧缓冲并销毁运行时纹理。
- 文件缺失时显示“该阶段视频指引待补充”。
- 文件损坏或无法解码时显示“视频加载失败”。
- 超过 20 MB 只会记录警告，不代表一定能够流畅运行。

## 9. 美术交付清单

- [ ] 六个文件齐全，文件名和大小写完全正确。
- [ ] 全部为 `960 × 540`、16:9。
- [ ] 全部为 GIF87a/GIF89a，优先 GIF89a。
- [ ] 帧率不超过 20 fps，推荐 15 fps。
- [ ] 单段不超过 30 秒，推荐 8～15 秒。
- [ ] 单文件不超过 20 MB，目标不超过 12 MB。
- [ ] 设置为无限循环，首尾没有明显闪白或长黑屏。
- [ ] 没有透明背景、编辑器界面、任务栏、Gizmo 或调试信息。
- [ ] 没有把流程指引卡片或视频弹窗录进 GIF。
- [ ] 关键操作在缩小到约 `857 × 482` 后仍容易辨认。
- [ ] `VerifyExtinction.gif` 能明显看出亮态到消光的变化。
- [ ] `ObserveConoscopic.gif` 能明显看出锥光干涉图样。
- [ ] 两段探头更换 GIF 中，目标探头和最终双击对象没有混淆。

## 10. Unity 验收建议

将 GIF 放入最终目录后，在 Unity 中进入 `Scene2.The Lab` Play Mode：

1. 依次切换六个阶段并打开“视频指引”。
2. 确认标题、GIF 文件和当前阶段一致。
3. 检查第一帧加载、播放速度、循环衔接和关闭后的资源释放。
4. 在 `1920×1080`、`1600×900`、`1366×768` 下检查画面完整、无裁切、操作可辨认。
5. 关注 Console 是否出现文件缺失、解码失败或超过 20 MB 的警告。
