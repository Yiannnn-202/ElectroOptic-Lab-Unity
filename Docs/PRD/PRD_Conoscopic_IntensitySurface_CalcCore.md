# PRD：锥光干涉图光强曲面计算核心

## 文档信息

| 项目 | 内容 |
|------|------|
| 项目名称 | 锥光干涉图附加实验：光强曲面计算核心 |
| 版本 | v1.0 |
| 创建日期 | 2026-05-13 |
| 所属范围 | 新附加实验场景的计算核心 |
| 当前边界 | 仅定义计算核心与接口契约，不包含 UI 设计、场景搭建和调度脚本落地 |

---

## 1. 背景与目标

当前 Scene2 中的锥光干涉图以二维纹理形式展示，能够表达干涉环、消光刷和单轴/双轴晶体特征，但呈现维度较单薄。后续希望支持用户双击锥光干涉图进入一个附加实验场景，在新场景中以 `x/y/z` 三维曲面展示锥光干涉图的具体光强分布，其中 `z` 轴表示归一化光强。

本阶段目标是先建设独立的计算核心，使其能够在没有新 UI 的情况下输出稳定、可调、可测试的光强网格数据。后续 UI 和调度脚本只负责进入场景、绑定参数控件、消费计算结果并渲染三维曲面。

---

## 2. 功能范围

### 2.1 包含内容

- 新计算核心接收晶体 Profile 与锥光显示参数，输出规则网格形式的光强数据。
- 计算核心默认使用 Scene2 当前选择的晶体 Profile，但进入新场景后参数状态与 Scene2 独立。
- 新场景内允许切换晶体，切换只影响本计算核心，不回写 Scene2 或全局 `CrystalSelectionData`。
- 计算结果需要尽量严格复刻当前 `ConoscopicInterference.shader` 的显示逻辑，保证二维锥光图与三维光强曲面能够对应。
- 提供清晰的接口契约，方便后续 UI、双击跳转和三维曲面渲染接入。

### 2.2 不包含内容

- 不设计或实现新场景 UI。
- 不实现双击跳转脚本。
- 不实现三维曲面 Mesh、材质、相机和交互。
- 不修改 Scene2 现有锥光干涉图交互逻辑。

---

## 3. 用户故事

作为实验学习者，我希望在观察 Scene2 锥光干涉图时，可以进入附加实验场景，从三维光强曲面角度理解干涉图中亮暗环、消光刷和晶体参数变化之间的关系。

作为后续 UI 开发者，我希望计算核心提供独立、稳定的参数输入和网格输出，使 UI 控件与曲面渲染可以在不理解底层光学公式的情况下完成接入。

---

## 4. 输入参数

### 4.1 晶体与物理输入

| 参数 | 类型 | 默认/来源 | 说明 |
|------|------|-----------|------|
| `profile` | `CrystalProfile` | 初次进入时使用 Scene2 当前选择晶体 | 晶体折射率、波长、长度等基础数据来源 |
| `crystalRotation` | `Vector2` 或等价角度结构 | `(0, 0)` | 新场景内独立的锥光计算旋转参数，不读取 Scene2 当前旋转 |
| `worldLightDirection` | `Vector3` | 复用现有锥光工作几何默认值 | 由核心内部或桥接层按现有规则解析 |

### 4.2 锥光显示参数

以下参数默认值与当前 Scene2 锥光纹理渲染器保持一致，但在新场景中独立维护：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `fov` | `10` | 视场角，影响视场坐标到光线方向的映射 |
| `phaseScale` | `0.1` | 相位缩放 |
| `displayGamma` | `1.25` | 显示伽马校正 |
| `blackCutoff` | `0.012` | 黑场截断 |
| `ringSharpness` | `1.0` | 环纹锐度 |
| `crossWidth` | `0.16` | 消光刷宽度 |
| `initialMelatopeOffset` | `(0.035, -0.025)` | 初始黑点偏移 |
| `laserColor` | `Color.red` | 显示元数据；第一版光强输出不直接输出颜色 |

### 4.3 网格参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `resolution` | `int` | 光强网格分辨率，必须可配置 |
| `xRange` / `yRange` | 固定为视场坐标 | 第一版使用当前锥光图一致的归一化视场坐标，范围为 `[-1, 1]` |

分辨率默认值由实现阶段根据性能测试确定，建议优先评估 `128 x 128` 与 `256 x 256`。

---

## 5. 输出定义

### 5.1 主输出

计算核心输出规则网格数据：

```text
point[i, j] = {
  x: float,          // 视场坐标 x，范围 [-1, 1]
  y: float,          // 视场坐标 y，范围 [-1, 1]
  intensity: float   // 归一化光强，范围 [0, 1]
}
```

其中 `intensity` 作为未来三维曲面的 `z` 值。视场圆孔外的点保持在规则矩阵内，但 `intensity = 0`，与当前 shader 黑色背景一致。

### 5.2 辅助输出

输出结果应包含当前参数快照，至少包括：

- 当前 `CrystalProfile`
- 网格分辨率
- 当前锥光显示参数
- 当前晶体旋转参数
- 是否完成有效计算

---

## 6. 计算规则

### 6.1 与当前 shader 保持一致

CPU 计算核心应复刻 `ConoscopicInterference.shader` 的主要显示路径：

- 使用当前 Fresnel 方程计算两条传播本征折射率。
- 通过 `delta_n`、晶体长度、波长和 `phaseScale` 计算相位差。
- 单轴晶体使用单个 optic axis / melatope 消光图样。
- 双轴晶体使用当前双 optic axis / 双 melatope 教学近似。
- 环纹强度、消光刷、圆孔 aperture、`blackCutoff`、`displayGamma`、`ringSharpness`、`crossWidth` 与 shader 逻辑保持一致。

### 6.2 CPU 近似要求

当前 shader 使用 `fwidth(gamma)` 处理环纹可见度。CPU 计算核心没有 GPU 屏幕导数，因此应使用有限差分估算相邻网格点的 `gamma` 变化，用于近似 shader 中的环纹锐度与远端衰减。

第一版验收标准是视觉趋势和主要强度分布与当前二维锥光图一致，不要求逐像素完全一致。

### 6.3 晶体计算依赖

核心应复用独立的 `CrystalPhysicalCore` 实例或等价桥接组件获取：

- `NewPrincipalIndices`
- `ShaderWorldToPrincipalMatrix`
- 当前 `CrystalConfig`

不得直接依赖 Scene2 运行时对象或 `CrystalRuntime`。Scene2 只负责在进入新场景时提供默认晶体 Profile。

## 7. 接口契约

### 7.1 建议模块形态

建议新增独立模块，例如：

```text
ElectroOptics.ConoscopicAnalysis
  ConoscopicIntensityCore
  ConoscopicIntensityParameters
  ConoscopicIntensityResult
```

命名可在实现阶段按项目目录规范微调，但职责必须保持独立。

### 7.2 核心职责

`ConoscopicIntensityCore` 应提供以下能力：

- 初始化时注入或创建独立 `CrystalPhysicalCore`。
- 设置当前 `CrystalProfile`。
- 设置锥光显示参数。
- 设置晶体旋转参数。
- 设置网格分辨率。
- 参数变化后标记 dirty。
- dirty 状态下重算整张光强网格。
- 重算完成后触发结果更新事件，例如 `OnIntensityUpdated`。

### 7.3 与未来调度脚本的关系

未来调度脚本负责：

- 从 Scene2 双击入口进入新场景。
- 将进入时的默认 `CrystalProfile` 注入计算核心。
- 将 UI 控件变化映射到计算核心 setter。
- 监听计算核心输出事件并刷新三维曲面。

计算核心不负责场景跳转、UI 控件、Mesh 构建或相机控制。

---

## 8. 更新策略

- 任意输入参数变化后，计算核心进入 dirty 状态。
- dirty 状态下重算完整网格。
- 重算完成后更新结果快照并发出事件。
- 不要求每帧重算；若参数未变化，应保持上一次结果。
- 未来若 UI 需要拖拽连续调参，可在调度层做节流，计算核心只保证单次重算正确。

---

## 9. 验收标准

1. 使用默认参数和同一晶体 Profile 时，三维曲面的俯视强度分布应与 Scene2 当前锥光图主要图样一致。
2. 修改 `fov` 后，光强分布应按视场角变化重新映射。
3. 修改 `phaseScale` 后，环纹密度或相位表现应发生可观察变化。
4. 修改 `displayGamma`、`blackCutoff`、`ringSharpness`、`crossWidth` 后，输出强度应体现对应显示 shaping 效果。
5. 单轴晶体应保留单 melatope / 单消光刷表现。
6. 双轴晶体应保留双 melatope / 双消光刷教学表现。
7. 圆孔外网格点强度必须为 `0`。
8. 新场景内切换晶体只影响本计算核心，不改变 `CrystalSelectionData.SelectedProfile`。
9. 不依赖 Scene2 的运行时 `CrystalRuntime`，直接进入新场景并手动注入 Profile 时也能计算。

---

## 10. 风险与后续事项

- CPU 有限差分只能近似 shader 的 `fwidth`，高频环纹区域可能与 GPU 结果存在细节差异。
- 高分辨率网格可能带来 CPU 开销，需要在实现阶段测试 `128 x 128` 与 `256 x 256` 的交互性能。
- 当前需求不包含 UI，因此参数控件布局、三维曲面样式、相机交互、双击入口反馈等由后续 PRD 或实现计划补充。
- 若后续希望输出 RGB 曲面或热力图颜色，可在现有归一化强度输出基础上增加颜色映射层，不应改变本核心的基础强度契约。
