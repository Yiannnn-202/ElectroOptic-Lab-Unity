## 1. 背景与现状

Scene2 当前同时存在两套实验指引：

1. **静态图片手册**：通过场景中的 `Btn_Guide` 打开四页 PNG 指引，适合用户完整阅读实验流程。
2. **实时卡片指引**：由 `Scene2CardGuide` 每帧读取实验状态，自动判断当前步骤是否完成，并切换到下一步。

现有实时指引具有以下问题：

- 展开、隐藏只有两种状态，无法收起成长条并持续展示进度。
- 步骤按场景对象查找结果动态增删，缺少稳定的阶段标识，无法安全绑定逐阶段 GIF。
- 状态判定与 UI、目标箭头逻辑集中在同一脚本中，后续扩展和测试困难。
- 激光校准可以直接按 Enter 完成，没有验证红点是否居中。
- 多数组件只检查是否在导轨上，没有验证真实光路顺序。
- 消光只检查偏振器角度，没有同时验证实际光屏强度。
- 现有目标圈、连线、箭头和模拟光标会增加画面干扰，本次不再保留。

本次重设计保留静态图片手册作为独立入口，只改造自动判定实验状态的实时卡片。

## 2. 产品目标与非目标

### 2.1 产品目标

- 将实时卡片改造成默认展开、可收起、可再次展开的常驻教学 UI。
- 将原有细碎步骤整理为六个稳定的实验教学阶段。
- 修复激光校准、消光和导轨顺序中的明显判定漏洞。
- 为每个阶段提供独立的 GIF 视频指引入口。
- 视频弹窗打开时形成真正的模态状态，禁止用户继续操作实验装置。
- 在常见 16:9 分辨率下保持卡片和视频弹窗可用、无遮挡、文字可读。
- 将状态判定、卡片 UI、GIF 播放和交互锁解耦，便于独立测试和替换。

### 2.2 非目标

- 不修改或删除现有四页 PNG 手册及其 `Btn_Guide` 入口。
- 不增加拖拽卡片、手动跳步、上一步/下一步按钮。
- 不提供“退出引导”或“重新开始”功能。
- 不保存跨场景、跨应用运行的指引进度或折叠状态。
- 不在完成页播放第六阶段或全流程 GIF。
- 不调整现有光学物理、器件移动和相机业务规则；新功能通过适配层读取状态。
- 本文档不包含开发工时和排期估算。

## 3. 用户流程

```text
进入 Scene2
  ↓
实时卡片在默认全局视角左上角展开
  ↓
系统从阶段一开始读取真实实验状态
  ↓
条件稳定满足 0.5 秒
  ↓
卡片显示约 0.6 秒完成反馈
  ↓
进入下一阶段（进度只前进、不回退）
  ↓
阶段六完成后驻留“实验操作指引已完成”状态
```

用户可以随时：

- 点击标题长条或三角图标收起/展开卡片。
- 按 F1 收起/展开卡片。
- 在展开状态点击“视频指引”，查看当前阶段 GIF。
- 通过弹窗下方“关闭”按钮或 Esc 退出视频弹窗。

## 4. 实时卡片需求

### 4.1 布局与视觉

| 项目 | 规格 |
|------|------|
| 位置 | 默认全局视角左上角，参考边距 32px |
| 展开尺寸 | 约 460×240px |
| 收起尺寸 | 约 460×52px |
| 视觉风格 | 深色半透明背景、青蓝描边和强调色，沿用现有科技感风格 |
| 中文字体 | 使用项目已有的 `SIMHEI SDF` 或同等中文字体资源 |
| 展开/收起动画 | 约 0.2 秒，使用非缩放时间驱动 |
| 阶段完成反馈 | 约 0.6 秒青蓝/绿色高亮，不播放音效 |

### 4.2 收起状态

收起栏必须完整表达该 UI 的用途和当前进度：

```text
实时操作指引 ｜ 阶段 n/6 ｜ 当前阶段标题                      ▼
```

- 整个标题长条和右侧三角均可点击。
- 收起后自动判定和阶段推进继续运行。
- 收起期间阶段发生变化时，只更新长条文字并短暂变色，不自动展开。
- 不显示目标圈、连线、箭头或模拟光标。

### 4.3 展开状态

```text
┌──────────────────────────────────────────┐
│ 实时操作指引 ｜ 阶段 n/6             ▲ │
├──────────────────────────────────────────┤
│ 当前阶段标题                             │
│                                          │
│ 当前阶段的完整操作说明。                 │
│                                          │
│                              [视频指引]  │
└──────────────────────────────────────────┘
```

- 正文直接显示完整文字说明，不另设“文字指引”按钮。
- “视频指引”按钮仅在六个教学阶段中显示。
- 完成页不显示视频、重启、退出或其他操作按钮。
- 进入 Scene2 时默认展开；重新加载 Scene2 后仍从默认展开状态开始。

### 4.4 完成状态

阶段六完成后：

- 展开卡片显示标题“实验操作指引已完成”。
- 正文显示“已完成全部装置搭建与探头切换，可以继续后续实验操作。”
- 收起栏显示“实时操作指引｜已完成”。
- 卡片继续允许展开/收起，但不再判定阶段，不提供重新开始。

## 5. 相机视角与可见性

实时卡片只允许在**默认全局视角**显示。

| 相机状态 | 卡片显示 | 状态判定 |
|----------|----------|----------|
| 默认全局视角且相机已停止移动 | 显示 | 继续 |
| 正视图 | 隐藏 | 继续 |
| 俯视图 | 隐藏 | 继续 |
| 任意器件特写 | 隐藏 | 继续 |
| 进入或退出视角的相机过渡中 | 隐藏 | 继续 |
| 视频弹窗打开 | 被遮罩覆盖 | 暂停 |

实现要求：

- 进入非默认视角时立即隐藏，不改变用户原有展开/收起选择。
- 返回默认视角后，必须等待相机位置和旋转真正回到初始值且过渡结束，再恢复卡片。
- 恢复时沿用进入其他视角前的展开/收起状态。
- 不仅依赖 `ExperimentCameraController.IsInCloseUpView`，还要识别正视、俯视和相机移动状态。

## 6. 六阶段定义与自动判定

### 6.1 共通规则

- 阶段使用稳定 `StageId`，不得使用运行时数组下标作为业务标识。
- 每个阶段条件必须连续满足 0.5 秒才算完成。
- 完成后先显示约 0.6 秒完成反馈，再切换到下一阶段。
- 进度单向前进；已经完成的阶段不因后续装置变化而回退。
- 当前阶段所需的前置条件被破坏时，保持当前阶段且不完成。
- 用户提前完成后续动作时，到达对应阶段后可以自动识别并完成。
- 组件顺序按照激光实际传播方向投影比较，不硬编码世界坐标 X 正负方向。
- 名称查找只作为缺失 Inspector 引用时的兼容回退，发生回退时必须输出明确警告。

### 6.2 阶段表

| StageId | 标题 | 正文 | 完成条件 |
|---------|------|------|----------|
| `PlaceScreen` | 放置光屏 | 点击光屏，使用 WASD 将它移动到光学导轨并按 Space 放下，确认屏幕已接收到激光。 | 光屏 `isOnRail == true`，且持续收到强度大于 0 的有效光数据。 |
| `CalibrateLaser` | 校准激光 | 微调激光位置，使红点进入光屏中心区域；对准后按 Enter 锁定校准。 | 红点进入以 512×512 屏幕中心 `(256,256)` 为中心的 `64pt×64pt` 方形判定区（对应遥测坐标中的 64×64 像素，即 X、Y 各允许 ±32）并稳定 0.5 秒；只有此时 Enter 才有效。范围外按 Enter 不完成，也不显示额外错误提示。 |
| `VerifyExtinction` | 验证消光 | 依次放置起偏器和检偏器。先将二者调至近似平行建立亮态基准，再把检偏器调至正交，使光屏接近消光。 | 顺序为激光→起偏器→检偏器→光屏；先在两偏振器近似平行（夹角不超过 8°）时记录有效亮态；之后夹角达到 `90°±8°`，且屏幕强度不高于亮态基准的 5%。没有亮态基准时不得完成。 |
| `ObserveConoscopic` | 观察锥光干涉 | 将晶体放在两偏振器之间，再将扩束镜放到晶体前方，保持光屏在轨并观察锥光干涉图样。 | 顺序为激光→起偏器→扩束镜→晶体→检偏器→光屏，所有组件均在轨，且 `UnifiedScreenPanel.CurrentMode == Conoscopic`。不要求进入特写或旋转晶体。 |
| `InstallPowerMeterProbe` | 更换光功率计探头 | 取下光屏和扩束镜，将光功率计探头放到晶体后方的导轨上。 | 光屏、扩束镜和光电二极管均离轨；`接收器.fbx` 对应的光功率计探头上轨；顺序为激光→起偏器→晶体→检偏器→光功率计探头。 |
| `InstallPhotodiodeProbe` | 更换光电二极管探头 | 取下光功率计探头，将光电二极管探头放到晶体后方的导轨上。 | 光屏、扩束镜和光功率计探头均离轨；`光电二极管.fbx` 上轨；顺序为激光→起偏器→晶体→检偏器→光电二极管探头。 |

### 6.3 消光亮态基准

- 基准只在 `VerifyExtinction` 阶段采集。
- 光路顺序正确、光屏正在收光、两偏振器夹角不超过 8°并稳定 0.5 秒后，记录当前实际屏幕强度作为亮态基准。
- 在亮态有效期间继续记录最大值，避免瞬时噪声导致基准过低。
- 若进入阶段时已经处于暗态，正文状态区提示“请先将检偏器调至亮态以建立基准”。
- 用户必须先产生有效亮态，再旋转到消光状态；禁止退化为固定绝对阈值或只判断角度。

## 7. 视频指引弹窗

### 7.1 基础交互

点击“视频指引”后：

1. 记录当前卡片和场景交互状态。
2. 暂停实时阶段计时和推进。
3. 显示全屏暗色遮罩，将弹窗置于所有 Scene2 UI 之上。
4. 加载当前阶段 GIF；加载完成后从第一帧静音循环播放。
5. 用户点击下方“关闭”按钮或按 Esc 后关闭弹窗。
6. 释放本次播放资源，恢复打开前的场景交互状态和卡片状态。

遮罩点击不能关闭弹窗。

### 7.2 弹窗布局

```text
┌──────────────────────────────────────────────────────────┐
│ 当前阶段标题 ｜ 视频指引                                │
├──────────────────────────────────────────────────────────┤
│                                                          │
│                 GIF 按原比例完整显示                     │
│                 允许留边，不允许裁切                     │
│                                                          │
├──────────────────────────────────────────────────────────┤
│                         [关闭]                           │
└──────────────────────────────────────────────────────────┘
```

- 使用与实时卡片一致的深色半透明、青蓝强调风格。
- 遮罩建议使用 60%～70% 黑色透明度，确保背景明显压暗。
- 弹窗根据当前分辨率等比缩放，不能超出安全区域。
- GIF 显示区域保持资源原始宽高比，使用 Fit 模式。

### 7.3 模态交互锁

弹窗打开期间：

- 禁止 3D 对象的 `OnMouseDown`/射线点击。
- 禁止 WASD、方向键、A/D、Space、Enter、旋钮长按和相机切换等实验输入。
- 禁止实时指引响应 F1。
- 暂停阶段稳定计时、完成反馈计时和步骤推进。
- 不设置 `Time.timeScale = 0`，非交互视觉和 GIF 继续运行。
- 不能禁用 EventSystem，因为关闭按钮仍依赖它。
- 关闭时必须按打开前记录的启用状态精确恢复，不能无条件启用所有组件。

建议由独立交互锁组件统一管理：

- 全屏 uGUI 遮罩拦截普通 UI。
- 临时保存并清空主相机的 3D 事件掩码，阻断 `OnMouseDown`。
- 临时禁用已登记的键盘输入控制器，并保存各组件原始 `enabled` 状态。
- 使用 `try/finally` 等价的清理流程，保证异常关闭或对象销毁时也能恢复。

### 7.4 加载、缺失与错误状态

| 状态 | 显示 |
|------|------|
| 文件不存在 | “该阶段视频指引待补充” |
| 正在读取/解码 | “正在加载视频指引……”及加载指示 |
| 文件损坏或解码失败 | “视频加载失败：文件名”，同时记录完整错误日志 |
| 正常 | 从第一帧开始循环播放 |

无论处于何种状态，“关闭”按钮和 Esc 都必须可用。

## 8. GIF 资源契约

### 8.1 目录与文件名

素材目录：

```text
Assets/StreamingAssets/ExperimentGuide/
```

阶段文件名固定为：

```text
PlaceScreen.gif
CalibrateLaser.gif
VerifyExtinction.gif
ObserveConoscopic.gif
InstallPowerMeterProbe.gif
InstallPhotodiodeProbe.gif
```

当前阶段不得通过数组序号拼接路径，必须通过 `Scene2GuideStageId` 映射固定文件名。

### 8.2 素材规格

| 项目 | 上限/要求 |
|------|-----------|
| 文件格式 | GIF87a 或 GIF89a |
| 最大建议分辨率 | 960×540 |
| 最大建议帧率 | 20fps |
| 最大建议时长 | 30 秒 |
| 最大建议文件大小 | 20MB |
| 音频 | 无 |
| 画面适配 | 保持比例、完整显示、不裁切 |

超出建议规格时播放器应记录警告；不承诺流畅播放。

### 8.3 解码依赖

- 使用 MIT 许可的 [3DI70R/Unity-GifDecoder](https://github.com/3DI70R/Unity-GifDecoder) 作为 GIF 解码核心。
- 引入时固定具体 commit，不允许依赖浮动 `master`；将 commit SHA 记录在第三方说明中。
- 第三方源码放入独立目录并保留原始 `LICENSE`。
- 项目自有播放器只依赖内部 `IGuideGifPlayer`，UI 和阶段控制器不得直接调用第三方类型。
- 播放器使用有界帧缓冲，不一次性长期保留整段 GIF 的全部 `Texture2D`。
- 关闭弹窗、切换场景或销毁播放器时，取消解码任务并释放创建的纹理。

## 9. 技术架构

### 9.1 模块划分

```text
Scene2CardGuide
├── Scene2GuideStageDefinition（六阶段固定配置）
├── IScene2GuideStateProvider（实验状态快照与完成判定）
├── Scene2CardGuideView（展开/收起/完成反馈）
├── Scene2GuideCameraVisibility（默认视角可见性）
└── Scene2GuideGifPopup
    ├── IGuideGifPlayer
    └── Scene2GuideInteractionLock
```

### 9.2 稳定类型

```csharp
public enum Scene2GuideStageId
{
    PlaceScreen,
    CalibrateLaser,
    VerifyExtinction,
    ObserveConoscopic,
    InstallPowerMeterProbe,
    InstallPhotodiodeProbe
}
```

阶段定义至少包含：

```csharp
public sealed class Scene2GuideStageDefinition
{
    public Scene2GuideStageId Id;
    public string Title;
    public string Body;
    public string GifFileName;
}
```

状态提供器至少暴露：

```csharp
public interface IScene2GuideStateProvider
{
    Scene2GuideStateSnapshot Capture();
    bool IsStageComplete(Scene2GuideStageId stageId, Scene2GuideStateSnapshot snapshot);
}
```

GIF 播放器至少暴露：

```csharp
public interface IGuideGifPlayer
{
    bool IsPlaying { get; }
    void Open(Scene2GuideStageId stageId, string absoluteOrStreamingAssetPath);
    void Close();
}
```

具体签名可按 Unity 生命周期调整，但稳定 StageId、状态提供器边界和播放器适配层不可取消。

### 9.3 状态引用

状态适配器必须显式区分并优先使用序列化引用：

- 激光器与激光校准控制器。
- 光屏与 `DirectScreenController`。
- 起偏器和检偏器。
- 扩束镜。
- 晶体。
- `接收器.fbx` 对应的光功率计探头。
- `光电二极管.fbx` 对应的光电二极管探头。
- 光学导轨。
- `UnifiedScreenPanel`。
- 主相机、默认相机位置及相关相机控制器。

红点坐标和实际屏幕强度由新建状态适配器读取；不得在 UI 控制器中重复物理计算。

### 9.4 场景与 Editor 工具升级

- 保留现有 `Scene2CardGuide.cs` 和 `Scene2CardGuideView.cs` 的资源 GUID，避免场景出现 Missing Script。
- 升级 Scene2 中现有 `Scene2CardGuideRoot`，不在运行时并存新旧两套卡片。
- 更新 `Scene2CardGuideSceneBuilder`，使其能够检测旧结构并执行升级/修复，而不是发现旧 View 后直接返回。
- 运行时 fallback UI 与场景可编辑 UI 必须拥有一致的层级、引用和行为。
- Bootstrap 仅在 Scene2 确实不存在控制器时创建兜底实例。

## 10. 非功能需求

| ID | 要求 |
|----|------|
| NF-01 | 兼容 Unity 2022.3.62f2c1 和当前无 asmdef 的工程结构 |
| NF-02 | 不修改原有光学器件业务脚本，通过新适配器扩展 |
| NF-03 | UI 动画和 GIF 播放使用非缩放时间，不依赖 `Time.timeScale` |
| NF-04 | GIF 解码不能阻塞主线程造成长时间无响应；首帧未就绪时显示加载态 |
